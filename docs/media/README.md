# Media

`recover-data-from-optical-media.gif` is generated by `test-harness/ui/capture-recover-data-gif.js` - a handful
of real screenshots of the app (via Playwright's `win.screenshot()`, the same reliable primitive
`capture-readme-screenshots.js` uses), stitched into one animated GIF. Not a staged mockup, and not a real screen
recording either - see that script's own header comment for why (Playwright's built-in video recording,
`recordVideo`, is a confirmed unresolved upstream bug on Electron + Windows - it made the app window open
completely blank when tried here).

Goes all the way through a real recovery - two real virtual `.iso` discs get built and mounted, one holding a real
split piece of a large file - so it actually shows the disc-swap, the real "Partial files detected" / "Yes,
reassemble" merge offer, and the final "Data recovery successful" dialog, not just the file-selection screen.

Embeds directly in `README.md` like any other GIF (see the existing feature icons there) - no GitHub
upload/hosting step needed, unlike a real video file.

Re-run the script any time the UI changes enough that this goes stale - it always overwrites the same file name.
